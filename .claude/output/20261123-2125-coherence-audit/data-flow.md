# bfb data-flow coherence audit

Seat s-20261123-212503-a666, reviewer, read-only. Nothing was run: no build, no tests, no browser. Every finding below rests on lines I opened and read; anything I inferred without reading is marked UNCONFIRMED.

## Verdict

The settings and Saved layers are in better shape than the bug history suggests: the key-level settings diff (src/storage.ts:63-89), the echo bookkeeping in src/kv.ts, and the Saved "moved/known" marks do hold for the cases they were built for. The class is still open in four ways. (1) Anything that is a whole object or whole array under one key is last-writer-wins, and the newest stores (Open with, folder views, Marks, recents) copy that shape. (2) src/kv.ts does not echo a tab's own write to the tab's other copies, so a second in-memory copy of Settings in the same tab goes stale and can write an old array back, which is the "allowed folder erased" bug by another route (F1). (3) Whole-profile writes are not atomic with the load that supplied their base, so tabs that load at the same time lose each other's history (F2). (4) Several stores are read with a shape check that is whole-or-nothing, or none, so one bad row empties the store and the next write makes it permanent (F9, F10). The top three to fix are F1, F2 and F3.

One correction to the brief: `background.js` is not built from `src`. `build.ts` has no entry for it (entries are listed at build.ts:7-69), so it is a hand-edited file that cannot import the key constants the rest of the code shares (F20).

## Areas checked and found clean

- Message channels: every sent type has a handler and every handler (apart from `inTab`) has a sender; the LLM port frames all have branches in src/llm.ts (see table above).
- site-bridge: `window.postMessage` use is source-checked, origin-targeted and the tile is validated against the fixed grid (src/site-bridge.ts:41-53); the page cannot poison the transit cache with its own text because only fetched Overpass output is stored (site-bridge.ts:57-59).
- Lights (`bfb-lights-v1`): readers validate (src/site-lights-settings.ts:24-29), all writers re-read before writing, and four listeners hear changes including the worker's early-stylesheet sync (background.js:454-459).
- The diff-based settings save itself: a scalar saved from a stale copy cannot undo another copy's scalar (storage.ts:74-89). F1 and F7 are the array-valued and same-tab-copy gaps around it.
- Saved first move: create-only writes, marked after the files exist, backup kept (saved-sync.ts:113-125), safe when two tabs run it at once.
- Notes files: atomic temp-file replace with fsync (native/notes_host.py:170-178) and an mtime guard on note writes (src/notes.ts:94, docs/notes-contract.md:88-90). The `.saved` batch write has no mtime guard (native/notes_host.py:1290-1299), a one-round-trip window I did not weigh as a finding.
- Strip state per tab (sessionStorage) with recovery copy keyed per tab id (apart from F14).
- loader.js reads of `bfbPageBg-*` are regex-checked before use (loader.js:31-39).
