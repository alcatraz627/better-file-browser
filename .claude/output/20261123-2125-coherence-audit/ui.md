# UI coherence audit (ui seat)

## Verdict

The Settings add-ons from 2026-11-20 mostly follow the system where it counts. Every new pane builds its switches, dropdowns, segmented controls and empty states from `src/controls.ts` and `emptyHtml`, and none of them uses a raw checkbox or `<select>`. The drift is in four places. (1) The note reminder and expiry menu in `src/note-meta-ui.ts` still carries native selects, raw checkboxes and an invalid `primary` variant, which is the largest visible break. (2) The two web-page plugins draw a separate design system inside a shadow root (amber accent, black primary button, its own button, segmented control and toast) and pick the dark-mode mode with a third component. (3) The newest Settings CSS hand-rolls parts that already exist (count pill, group heading, square buttons, empty state) and uses `9px` row corners where the census spec says `8`. (4) The ratchet `e2e/check-system.mjs` is red on 19 of 22 rules, so it no longer separates new drift from old. Nothing here needed a browser to confirm. Every row below was read in source. Anything inferred is marked UNCONFIRMED.

## Checked and found consistent

- The new Settings panes (Open with, Sections, Web pages, Folders with their own view) build every switch with `switchHtml`, every dropdown with `ddHtml`, every segmented control with `segHtml`, and every delete with `btn` `data-icon` `data-tone="danger"`, each with a `title` and `aria-label` (`settings-open-with.ts:56-61`, `settings-lenses.ts:26-29`, `settings-web.ts:53,74`, `settings-folder-views.ts:36`).
- No raw `type="checkbox"` or `<select>` in the new Settings files. The only raw checkboxes outside `controls.ts` are the sanctioned toggle wrapper in `page.ts:241-242`, the markdown task list (`renderers.ts:886`) and F1.
- Switches with state tooltips carry a separate `label` for screen readers, as `check-switch.md:19` asks (`settings-open-with.ts:59-60`, `settings-lenses.ts:29`).
- Empty states in Open with, Web sites, Marked pages and Folder views use `emptyHtml`.
- Settings search keeps the input on `.tb` `data-size="lg"` and uses `prefers-reduced-motion`-aware smooth scroll (`settings-search.ts:154`); its highlight uses the CSS highlight API, not DOM rewriting.
- The overlay does not fade or slide in; its only animation is the user-triggered pin flash (`site-tools-overlay.ts:53`).
- The overlay's `.btn` height 28 and `.icon-btn` 28 match `--ctl-md`; its dark and light switch follows the page.
- The Open with colour popover reuses `.fe-rule-pop` and the `.fe-rp-c` swatches from the icon rules, so the two colour pickers match.
